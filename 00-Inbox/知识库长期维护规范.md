# 知识库长期维护规范

> 适用范围：ChatGPT、GitHub 与 Obsidian 的协作维护。以 [[obsidian手册]] 的渐进完善与知识嵌合原则为基础。本文是可修订的工作约定，不取代既有学科分类。

## 一、权限边界

- **无需逐次结构审批的操作**：经明确要求，创建普通笔记；在核对现有内容后补充相关笔记；添加经过核实的链接；更新索引。
- **必须事先征得明确同意的结构性操作**：新增或重命名一级目录、移动或合并目录、批量重命名、批量修改、删除文件或历史、重构分类体系。
- 对覆盖原文、改变观点含义或可能产生冲突的修改，先提供差异摘要再执行。
- 没有“收录”“暂存”“完善”等明确指令时，默认只讨论，不自动写入。

## 二、日常输入指令

- **收录**：将本次讨论整理为 Markdown；先查重和判断归属，再提交新笔记或补充现有笔记。
- **暂存**：尽量保留原始表达，写入 `00-Inbox/`，标记为待整理。
- **完善**：读取目标已有笔记，保留其结构与论证脉络，提出或执行局部补充；涉及大幅改写先确认。
- **仅讨论**：不写入仓库。

## 三、分类规则

| 内容 | 首选位置 |
| --- | --- |
| 数学、物理概念和推导 | 对应学科 `Z笔记/` |
| 解题技巧、题型、备考复盘 | 对应学科 `A备考/`（已有时） |
| 化学具体物质 | `化学/Z物质/` |
| 化学概念与规律 | `化学/Z笔记/` |
| 跨学科基础知识 | `自然科学基础/` |
| 哲学观念、独立思辨 | `文学/哲学/` |
| 世界观、角色、创作项目 | `文学/世界观/` 对应项目 |
| 暂未定型或归属不明 | `00-Inbox/` |

不为缺失的 `A备考` 等目录擅自建立新的学科结构。文学随笔或日常记录若现有目录不适合，先进入 Inbox，并提出候选归属，待确认后再调整。

## 四、笔记撰写约定

- Markdown 使用清晰标题层级；公式用 Obsidian 可识别的 `$...$` 与 `$$...$$`；附件沿用 `Z附件/`。
- YAML 属性按需使用，优先 `type`、`status`、`created`、`updated`、`tags`；不强制改写旧文件。
- 学习笔记优先写清定义、适用条件、推导、例题与易错点；不要将不确定的猜测写成定理。
- 思辨笔记保留原始措辞，区分「原始想法」「整理与论证」「开放问题」；不擅自替作者确定立场。
- 创建链接前先检查目标文件是否存在，避免大量空链接；一个概念尽量维持一个主要知识节点。
- 引用外部资料时记录来源，避免把 AI 生成的推论伪装成原始材料。

## 五、GitHub 同步链

1. 工作日手机端讨论并明确提出收录/暂存/完善。
2. ChatGPT 读取当前 `main` 相关文件，检查是否已有同名或相关笔记。
3. 按约定写入，尽量一次任务一个独立 Commit；返回路径、修改摘要和提交结果。
4. 电脑端 Obsidian Git **先 Pull 再修改**；若有未提交本地改动，先备份或提交，避免冲突。
5. 本地修改完成后 Commit/Push；下一次云端写入前再次读取最新版本。
6. 发生冲突时停止覆盖，保留双方版本并由使用者决定合并方式。

## 六、定期维护

- **每周（可选）**：回顾 Inbox 待整理内容、检查失效链接与同步冲突。
- **每月（可选）**：评估重复知识节点、目录是否需要演化，先提出建议，不自动重构。
- 索引只维护导航和关系，不复制正文。
- 不设置自动后台写入；只有明确启动任务时才执行仓库操作。

## 七、修改本规范

规范可以随着实际使用修订。涉及权限边界或目录组织方式的修改，应先与仓库所有者确认。
